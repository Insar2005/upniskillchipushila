# SkillUp v29.2.1 — исправление резервной копии на iPhone

Исправляет ошибку Telegram iOS «Перейти по ссылке blob:...» после нажатия «Скачать локальную резервную копию».

## Что изменено

- На iPhone сначала используется системное меню «Поделиться». В нём выберите «Сохранить в Файлы», имя будет `skillup-local-backup-YYYY-MM-DD.json`.
- Если Telegram/WebView не разрешает передачу локального JSON-файла, появляется окно с «Скопировать JSON» и «Выделить текст». Сохраните текст в заметках/текстовом редакторе как JSON и проверьте, что он полный.
- В Chrome/десктопных браузерах оставлено стандартное скачивание файла.
- Формат резервной копии `skillup-local-backup-v1` не меняется. Архив включает `index.html` и `skillup-cloud.js` из v29.2 плюс **только** исправление экспорта; Node.js API и PostgreSQL не изменяются.

## Установка на Railway

1. Сохраните резервную копию репозитория (или commit).
2. Распакуйте ZIP. Замените содержимое файлов в репозитории **основного frontend**, не `skillup-api`.
3. Запустите Deploy через GitHub/Railway.
4. На iPhone в Telegram откройте «Профиль → Синхронизация SkillUp → Сохранить локальную резервную копию».
5. В стандартном меню iOS выберите «Сохранить в Файлы». Если доступна только кнопка копирования, используйте её и сохраните JSON вручную.

## Безопасность

Экспорт берётся **только из localStorage текущего Telegram WebView**. Данные не отправляются на сервер для скачивания. JSON содержит личные данные (финансовые записи, цели и заметки). Не публикуйте и не пересылайте его третьим лицам.

Автоматический локальный backup, который создаётся при импортировании или замене облачных документов, остаётся доступным в localStorage, но **не равен скачанному на устройство файлу**.

## Ограничения

Реальное системное меню «Поделиться» зависит от поддержки `navigator.share` / `navigator.canShare` в версии Telegram для iOS. Оно требует проверки на реальном устройстве. Если iOS WebView не поддерживает передачу JSON-файла, сработает запасной способ. Для полноценной нативной функции Telegram `downloadFile` потребуется отдельный защищённый HTTPS-маршрут выдачи backup; передавать персональные данные через публичный URL нельзя.
