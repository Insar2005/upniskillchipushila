# SkillUp v29.2 — осторожная синхронизация с существующим Railway API

**Обновляется только фронтенд SkillUp.** `skillup-api` и PostgreSQL в этом шаге не меняются.

## Требования

- Основной сайт: https://upniskillchipushila-production.up.railway.app/
- Существующий API: https://skillup-api-production-3d6c.up.railway.app
- API не ниже v0.2.1-authfix: `/api/v1/me` уже проверен в Telegram и отвечает 200.
- API с маршрутами `GET/PUT /api/v1/documents/development` и `.../finances` (v0.2.x).
- В `skillup-api → Variables` должен остаться `CORS_ORIGINS=https://upniskillchipushila-production.up.railway.app`.
- В Railway нет необходимости создавать другую БД, новые таблицы или второй API.

## Установка

1. Сохрани текущий frontend-репозиторий/последний рабочий commit.
2. Распакуй ZIP и загрузи эти файлы в **основной** GitHub-репозиторий сайта (в корень):
   `index.html`, `skillup-cloud.js`, `nginx.conf`, `Dockerfile`, `railway.toml`.
3. `README_УСТАНОВКА.md` можно тоже оставить в корне — Nginx его не выдаёт как часть интерфейса.
4. Дождись успешного frontend Deploy. Не изменяй `skillup-api`.
5. Открой SkillUp через Telegram-бота, затем **Профиль → Синхронизация SkillUp**.

## Первый запуск

- Для сохранения существующих *реальных* локальных данных нажми «Скачать локальную резервную копию», затем «Перенести мои локальные данные».
- Если данные только демонстрационные — сначала скачай копию, затем «Начать с пустого облака» (действие потребует подтверждения). Фиктивные операции и цели не копируются в PostgreSQL автоматически.
- Если на сервере уже есть документы, приложение предложит **только загрузить их** с локальным backup. Автоматически переписывать сервер содержимым браузера запрещено.
- В разделе Профиль статус «Облако ✓» означает, что сервер подтвердил сохранение, а «Не сохранено» — локальные изменения ещё не ушли.
- Если импорт начался, но второй документ не создался из-за сбоя сети, **не удаляй локальную копию**. Сначала посмотри, что уже находится в облаке, и согласуй восстановление.

## Проверка на двух устройствах

1. После подключения добавь направление и цель «Тест синхронизации» со своим регулярным действием.
2. В Финансах добавь ручной расход 150 ₽ (или нужную сумму).
3. В Профиле дождись «Облако ✓» (если ошибка — скриншот без личных данных).
4. Закрой Mini App и заново открой. Цель и расход должны остаться.
5. На **другом устройстве, тем же Telegram-аккаунтом** открой приложение → Профиль → «Загрузить из PostgreSQL». Сначала сделай локальный экспорт, если на другом устройстве есть свои данные. Убедись, что обе записи появились.

## Ограничения этапа

- Передаются только `development` (направления, цели, навыки, привычки, этапы, действия и их отметки) и `finances` (операции пользователя + цель накопления). Для защиты данных используются Telegram initData, серверный user_id и `revision` (HTTP 409 при конфликте).
- Сервер пока хранит **JSON-снимки** в `user_documents`, не нормализованные таблицы всех отдельных сущностей. Изменения с разных устройств одновременно могут давать HTTP 409; автоматического merge **нет**. Ни в коем случае не обходить конфликт удалением данных.
- Чаты/заметки/уроки ИИ и отдельные исторические snapshot'ы общей статистики пока остаются локальными; следующий этап — их безопасный перенос и отдельная серверная модель ИИ. Реальная LLM на этом этапе **не подключена**.
- Старые документы формата v25 `{items: {localStorageKey: string}}` не импортируются автоматически: это потребует отдельного явного migration step, чтобы не потерять пользовательские записи.
- Приложение не включает облачную синхронизацию вне Telegram и не импортирует демопакет без согласия. 401 не обходится.
- Резервные копии автоматически сохраняются в localStorage перед заменой; **скачиваемый JSON** — более надёжный способ не потерять их при очистке WebView.
