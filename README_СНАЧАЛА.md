# SkillUp v29 — этап A, проверка Telegram авторизации

## Назначение

Это **актуальный фронтенд v29** с исключительно диагностическим дополнением. Дизайн, локальная логика, финансы, развитие и ИИ-прототип не изменены. Синхронизация и настоящий ИИ намеренно пока НЕ включены: сперва нужно доказать, что существующий сервер Railway принимает Telegram initData.

## Что находится внутри

- index.html — v29 + скрытая диагностическая панель;
- Dockerfile, nginx.conf, railway.toml — конфигурация развертывания Nginx на Railway, перенесенная из предыдущего работающего frontend пакета;
- README_СНАЧАЛА.md — инструкции.

Никаких секретов и токенов в файлах нет. В коде диагностики используется HTTPS-адрес существующего API: https://skillup-api-production-3d6c.up.railway.app

## Как протестировать

1. Сделайте резервную копию текущего GitHub-репозитория фронтенда и экспорта пользовательского localStorage (если в нём есть реальные записи). Не удаляйте ни БД, ни старые данные.
2. Загрузите 4 рабочих файла в корень **фронтенд**-репозитория (НЕ `skillup-api`). Проверьте, что Railway обновил сервис сайта.
3. В Telegram откройте SkillUp через кнопку своего бота. **Пять раз быстро нажмите по надписи SkillUp в шапке**. Появится диагностическое окно. В обычном использовании его нет.
4. Диагностика показывает наличие SDK/initData/hash, возраст подписи и результат GET `/api/v1/me` (без вывода самой подписи или Telegram ID).
5. Пришлите снимок только этого диагностического окна. Ни BOT_TOKEN, ни DATABASE_URL, ни само initData присылать нельзя.

В качестве альтернативы можно открыть отладчик iframe приложения и вызвать `window.skillupOpenAuthDiagnostics()`.

## Интерпретация

- `initData ОТСУТСТВУЕТ` — SDK не получил Telegram launch credentials: проверить запуск/iframe.
- `HTTP 200` + пользователь найден — Telegram идентификация прошла. Следующий этап — безопасное чтение данных с сервера и миграция с подтверждением.
- `HTTP 401` при наличии hash — сервер отверг подпись; проверяем соответствие TELEGRAM_BOT_TOKEN используемому боту, возраст подписи и точный live-код API.
- `HTTP 503` — серверная конфигурация/БД недоступна.
- `Сетевой сбой/CORS` — проверить HTTPS, сервис и CORS_ORIGINS в Railway.

Важно: GET /me в существующей реализации может создать или обновить запись профиля в `users` — это часть авторизации. Он не создаёт и не изменяет цели, транзакции, чаты или локальные данные.

Эта версия не пытается исправить 401 подстановкой user_id и не отключает проверку Telegram-подписи.
